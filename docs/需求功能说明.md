# StockHunter 需求功能说明

## 1. 项目定位

StockHunter 面向需要长期记录交易决策并进行复盘的个人投资者。

系统目标不是替代券商下单，而是成为一套独立于交易平台之外的：

- 个人决策档案库
- 仓位分析工作台
- 交易纪律复盘系统

## 2. 产品目标

- 系统化记录单一标的的所有关键动作与判断
- 自动计算真实持仓成本与收益，不依赖人工心算
- 将价格、仓位、收益、复盘笔记统一在同一工作界面中
- 帮助用户在事后复盘时回答“为什么买”“为什么卖”“是否按纪律执行”
- 基于个人历史交易节奏与策略参数，推演后续更合适的买卖观察区间

## 3. 目标用户画像

- 会定投、波段、网格或趋势加减仓的个人投资者
- 同时持有基金、ETF、股票等多个资产，但希望逐个标的深度复盘
- 不满足于券商流水，想沉淀自己的交易体系和经验库
- 以工程化思维管理交易记录，希望数据结构清晰、结果可解释的用户

## 4. 功能范围

### 4.1 标的管理

- 新增交易标的
- 维护标的代码、名称、市场、资产类型、币种
- 维护标的层面的长期备注
- 配置策略参数：目标持仓金额、最大持仓金额、买入步长、卖出步长、反弹确认比例

### 4.2 交易账本

- 记录买入、卖出、现金分红、送股
- 记录成交数量、价格、手续费、税费、现金金额
- 记录交易原因、详细交易逻辑、主观信心分
- 交易流水按日期倒序展示，方便快速复盘

### 4.3 成本与收益分析

- 自动计算当前持仓数量
- 自动计算动态成本线
- 自动计算持仓成本、当前市值、浮动盈亏
- 自动计算已实现收益与分红收入
- 自动统计买入总额、卖出总额、交易成本

### 4.4 组合总览与贡献分析

- 汇总组合总市值、总成本、总盈亏、总份额
- 展示每个标的对组合总仓的资金占比
- 展示每个标的对总浮盈亏、总已实现收益的贡献比例
- 展示每个标的持有份额在总持仓份额中的参考占比
- 对负收益贡献标的做单独颜色提示，方便快速识别拖累项

### 4.5 价格快照与图表联动

- 手工录入关键日期价格
- 支持记录收盘价、参考价、最高价、最低价、成交量
- 支持记录行情备注
- 在图表中叠加价格轨迹与成本轨迹
- 在价格波动线上直接标注买入、卖出、分红、送股事件
- 鼠标悬浮时查看当日价格、成本差和交易详情

### 4.6 决策辅助

- 根据当前成本线、策略步长和历史波动率推演买入带
- 根据成本线、策略步长和盈利状态推演卖出带
- 结合最大持仓金额，给出仓位占用率提示
- 输出“观察中 / 买入关注 / 卖出关注 / 持有跟踪”状态
- 给出对应的执行建议文案，辅助后续纪律化操作

### 4.7 复盘档案

- 针对单个标的记录复盘笔记
- 记录复盘日期、标题、情绪标签、复盘正文、下一步计划
- 形成时间线，方便持续回看自己的判断演化

### 4.8 工具面板

- 提供基金卖出份额速算器
- 支持直接填写净值
- 支持根据当前持仓金额和持有份额反推净值
- 支持按目标卖出金额或目标保留金额两种方式计算
- 输出估算卖出份额、估算卖出金额、剩余份额、剩余金额

### 4.9 演示与初始化

- 提供演示数据写入能力
- 支持空库自动写入演示数据，由环境变量控制
- 支持脚本式重置数据库与重建演示数据

## 5. 关键业务规则

### 5.1 成本计算规则

- 买入：成本 = 数量 × 价格 + 手续费 + 税费
- 卖出：按卖出前平均成本冲减持仓成本，并将净卖出金额与冲减成本的差值计入已实现收益
- 分红：现金分红计入已实现收益，不改变持仓成本
- 送股：增加持仓数量，不额外增加成本

### 5.2 决策区间推导规则

- 买入带以动态成本线为基础，叠加买入步长和历史波动率折算
- 卖出带以动态成本线为基础，叠加卖出步长和历史波动率扩展
- 仓位占用率 = 当前市值 / 最大持仓金额
- 当价格进入买入带或卖出带时，系统切换到对应关注状态

### 5.3 表单与数据质量规则

- 标的目标持仓金额不得大于最大持仓金额
- 买入、卖出必须填写大于 0 的数量和价格
- 卖出数量不得超过当前持仓数量
- 分红必须填写大于 0 的现金金额
- 送股必须填写大于 0 的新增份额
- 价格快照中，最高价不得低于最低价，收盘价必须落在高低价区间内
- 复盘标题与正文在去除空白后不能为空

### 5.4 份额速算规则

- 基础公式：份额 × 净值 = 金额
- 输出卖出份额按 0.01 份保留两位小数
- 仅用于交易前速算辅助，不计赎回费、到账延迟和未知确认净值偏差

## 6. 非功能要求

- 可扩展：后续可接入自动行情抓取、提醒、导入导出
- 可维护：领域计算、表单校验、页面展示分层，便于长期演进
- 易部署：默认本地即可运行，不依赖外部数据库服务
- 数据可解释：数据库表、字段、配置项均带中文注释或说明
- 交互清晰：关键错误尽量在提交前暴露，避免脏数据写入

## 7. 当前版本技术决策

- 使用 Next.js App Router 统一页面、服务端动作、部署入口，降低维护成本
- 使用 Node.js 内置 `node:sqlite` 驱动本地 SQLite，避免额外数据库服务依赖，并保持良好的可移植性
- 使用 Zod 统一服务端输入约束，减少前后校验逻辑漂移
- 使用原生 SVG 绘图，避免引入重型图表依赖，减小系统体积
- 使用 Server Action 处理录入动作，减少重复 API 样板代码

## 8. 架构与安全边界

- 当前方案不是纯前端静态站，而是 `Next.js + Server Actions + SQLite` 的本地优先单体应用
- 页面渲染由 React 完成，但数据写入、表单兜底校验和核心分析计算都在服务端执行
- 数据库不会直接暴露给浏览器
- 当前版本的安全定位是单用户本地工具安全，不是公网多租户 SaaS 安全
- 若未来支持多用户或公网部署，需要补齐认证鉴权、CSRF、审计日志、速率限制、备份与敏感配置隔离

## 9. 当前版本交付内容

- 单标的交易记录与复盘工作台
- 组合总览、资金占比、收益贡献分析
- 买卖点与价格线联动图表
- 表单即时校验与服务端业务校验
- 基金卖出份额速算器
- 本地 SQLite 数据持久化
- 演示数据初始化与重置脚本
- 中文需求文档与操作指南

## 10. 后续可扩展方向

- 交易记录批量导入 CSV
- 多账户、多策略、多币种支持
- 标签体系与筛选器
- 风险提醒、邮件或通知中心
- 更细颗粒度的收益归因与网格策略模拟
