# StockHunter 操作指南

## 1. 环境准备

- Node.js 20 及以上
- pnpm 10 及以上

安装依赖：

```bash
pnpm install
```

## 2. 配置说明

复制配置文件：

```bash
cp .env.example .env.local
```

可用配置项：

- `NEXT_PUBLIC_APP_NAME`：页面标题显示名称
- `STOCKHUNTER_DB_PATH`：本地数据库文件路径
- `STOCKHUNTER_AUTO_SEED`：当数据库为空时是否自动写入演示数据

## 3. 初始化方式

### 3.1 方式一：先看演示数据

```bash
pnpm db:seed
pnpm dev
```

打开浏览器访问 `http://localhost:3000`，即可看到带演示数据的完整仪表盘。

### 3.2 方式二：从空白数据开始

```bash
pnpm dev
```

进入页面后，先在右侧“新增交易标的”表单中创建你的第一只基金/股票。

## 4. 建议录入流程

### 第一步：创建标的

至少补齐以下信息：

- 标的代码
- 标的名称
- 市场
- 资产类型
- 币种
- 目标持仓金额
- 最大持仓金额
- 买入步长 / 卖出步长 / 反弹确认比例

建议在备注中写清楚：

- 建仓逻辑
- 核心风险
- 计划持有周期
- 什么情况下暂停加仓

### 第二步：补录历史交易流水

在“新增交易流水”中逐条录入：

- 买入：填写数量、价格、手续费、原因
- 卖出：填写数量、价格、税费、原因
- 分红：数量和价格可以为 0，现金金额填写实际到账金额
- 送股：填写新增份额，价格通常为 0

建议同时填写：

- 交易原因
- 详细判断
- 信心分（1 到 5 分）

### 第三步：补录价格快照

为了让图表和决策区间更有参考价值，建议至少录入：

- 关键买点对应价格
- 大幅回撤低点
- 关键止盈位置
- 当前最新参考价

### 第四步：写复盘笔记

在每次重要加仓或减仓后新增一条复盘：

- 当时为什么做这个动作
- 哪些判断是对的
- 哪些地方是情绪化或没有按纪律执行
- 下一步如何调整

## 5. 页面阅读方式

### 左侧边栏

- 查看组合总市值与总盈亏
- 快速切换不同标的

### 主看板

- 顶部：当前标的的核心状态总览
- 价格带推演：价格、成本线、买入带、卖出带同屏显示
- 仓位轨迹：查看持仓数量与累计已实现收益变化
- 策略建议：系统给出的当前状态与执行建议
- 交易账本：逐笔核对历史动作
- 复盘时间线：回看判断与计划的变化

### 右侧工作台

- 新增交易标的
- 录入交易流水
- 维护价格快照
- 追加复盘笔记

## 6. 常用命令

```bash
pnpm dev        # 本地开发
pnpm lint       # 校验代码规范
pnpm typecheck  # 校验 TypeScript 类型
pnpm build      # 生产构建
pnpm db:seed    # 写入演示数据
pnpm db:reset   # 清空数据库表
```

如果你想重新演示完整流程：

```bash
pnpm db:reset
pnpm db:seed
```

## 7. 使用建议

- 不要只记录成交结果，要把“为什么做”一起写下来
- 一个标的至少维护一个清晰的最大持仓金额，否则建议区间会失去仓位约束意义
- 每周至少补一次最新价格快照，避免图表和建议长期失真
- 复盘时重点看“是否按计划执行”，而不只是结果赚钱还是亏钱

## 8. 常见问题

### Q1：为什么系统没有自动抓取实时行情？

当前版本优先保证本地可用、结构可维护，因此采用手工价格快照。后续可以在此基础上扩展自动抓取模块。

### Q2：为什么建议区间和我主观感觉不完全一致？

当前建议区间是基于历史交易、成本线、波动率和你设置的策略步长推导的，它是“纪律辅助”，不是替代你的最终判断。

### Q3：数据库文件在哪里？

默认在 `data/stockhunter.sqlite`，可以通过 `.env.local` 中的 `STOCKHUNTER_DB_PATH` 修改。
