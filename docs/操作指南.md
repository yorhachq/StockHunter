# StockHunter 操作指南

## 1. 环境准备

建议运行环境：

- Node.js 20 及以上
- pnpm 10 及以上

安装依赖：

```bash
pnpm install
```

## 2. 配置说明

复制配置文件：

```bash
cp .env.example .env.local
```

可用配置项：

- `NEXT_PUBLIC_APP_NAME`：页面标题显示名称
- `STOCKHUNTER_DB_PATH`：本地数据库文件路径
- `STOCKHUNTER_AUTO_SEED`：当数据库为空时是否自动写入演示数据

## 3. 初始化方式

### 3.1 先看演示数据

```bash
pnpm db:seed
pnpm dev
```

打开浏览器访问 [http://localhost:3000](http://localhost:3000)，即可看到带演示数据的完整仪表盘。

### 3.2 从空白数据开始

```bash
pnpm dev
```

进入页面后，先在右侧“新增交易标的”表单中创建你的第一只基金或股票。

## 4. 推荐录入流程

### 第一步：创建标的

至少补齐以下信息：

- 标的代码
- 标的名称
- 市场
- 资产类型
- 币种
- 目标持仓金额
- 最大持仓金额
- 买入步长、卖出步长、反弹确认比例

建议在备注中写清楚：

- 建仓逻辑
- 核心风险
- 计划持有周期
- 什么情况下暂停加仓

### 第二步：补录历史交易流水

在“新增交易流水”中逐条录入：

- 买入：填写数量、价格、手续费、原因
- 卖出：填写数量、价格、税费、原因
- 分红：数量和价格可以为 0，现金金额填写实际到账金额
- 送股：填写新增份额，价格通常为 0

建议同时填写：

- 交易原因
- 详细判断
- 信心分，1 到 5 分

### 第三步：补录价格快照

为了让图表和决策区间更有参考价值，建议至少录入：

- 关键买点对应价格
- 大幅回撤低点
- 关键止盈位置
- 当前最新参考价

### 第四步：阅读图表与组合贡献

录入足够数据后，可以重点看这几块：

- 左侧标的列表中的资金占比和浮盈贡献
- 中央价格图上的买入点、卖出点、分红点、送股点
- 鼠标悬浮图上节点时显示的当日交易详情与成本差
- 右侧策略建议中当前处于买入带、卖出带还是观察区间

### 第五步：使用基金卖出份额速算器

适合支付宝基金等“持仓页面看金额、卖出页面填份额”的场景。

使用方法：

- 如果你知道当前净值，直接填写净值
- 如果你不知道净值，可填写当前持仓金额和当前持有份额，让系统自动反推净值
- 选择目标模式：输入想卖出的金额，或者输入卖出后想保留的金额
- 查看结果中的“应卖份额”，将它作为平台卖出时的参考填写值

注意：

- 结果按 0.01 份估算
- 不包含赎回费和未知确认净值偏差
- 仅用于交易前速算，不会写入数据库

### 第六步：写复盘笔记

在每次重要加仓或减仓后新增一条复盘：

- 当时为什么做这个动作
- 哪些判断是对的
- 哪些地方是情绪化或没有按纪律执行
- 下一步如何调整

## 5. 页面阅读方式

### 左侧边栏

- 查看组合总市值、总盈亏、总份额
- 快速切换不同标的
- 观察每个标的的资金占比与收益贡献

### 主看板

- 顶部：当前标的的核心状态总览
- 价格带推演：价格、成本线、买入带、卖出带、买卖点同屏显示
- 仓位轨迹：查看持仓数量与累计已实现收益变化
- 策略建议：系统给出的当前状态与执行建议
- 组合贡献：查看当前标的对整体组合的影响比例
- 交易账本：逐笔核对历史动作
- 复盘时间线：回看判断与计划的变化

### 右侧工作台

- 新增交易标的
- 录入交易流水
- 维护价格快照
- 追加复盘笔记
- 使用基金卖出份额速算器

## 6. 表单与录入提示

- 表单同时具备浏览器约束、客户端即时提示和服务端兜底校验
- 如果卖出数量超过当前持仓，服务端会拒绝写入
- 如果价格快照高低价关系异常，系统会直接提示
- 如果复盘标题或正文只输入空格，也不会通过校验
- 提交按钮在处理中会禁用，避免重复点击造成误写

## 8. 架构与安全说明

当前项目并不是纯前端静态页面，而是一套本地优先单体应用：

- React 负责界面与交互
- Next.js Server Actions 负责写入入口
- 服务端领域层负责成本、收益、策略区间计算
- SQLite 负责本地数据持久化

当前安全边界：

- 浏览器不会直接访问数据库
- 所有录入动作都经过服务端校验
- 当前版本默认面向单用户本地使用

如果未来部署到公网或提供多用户能力，需要继续补充认证鉴权、权限隔离、速率限制、审计日志和备份方案。

## 9. 使用建议

- 不要只记录成交结果，要把“为什么做”一起写下来
- 一个标的至少维护一个清晰的最大持仓金额，否则建议区间会失去仓位约束意义
- 每周至少补一次最新价格快照，避免图表和建议长期失真
- 复盘时重点看“是否按计划执行”，而不只是结果赚钱还是亏钱
- 如果你主要做基金交易，建议每次卖出前先跑一遍份额速算器

## 10. 常见问题

### Q1：为什么系统没有自动抓取实时行情？

当前版本优先保证本地可用、结构可维护，因此采用手工价格快照。后续可以在此基础上扩展自动抓取模块。

### Q2：为什么建议区间和我主观感觉不完全一致？

当前建议区间是基于历史交易、成本线、波动率和你设置的策略步长推导的，它是“纪律辅助”，不是替代你的最终判断。

### Q3：数据库文件在哪里？

默认在 `data/stockhunter.sqlite`，可以通过 `.env.local` 中的 `STOCKHUNTER_DB_PATH` 修改。

### Q4：为什么有些校验提示前端已经提示了，服务端还会再拦一次？

因为前端提示主要是为了减少误操作，服务端兜底校验则是为了确保数据库不会落入脏数据。两层同时存在，才能兼顾体验和可靠性。
